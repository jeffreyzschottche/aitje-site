# 25 New game levels every week. With no external token costs.

Official page: https://aitje.com/en/cases/coder-game-in-24-uur

> A marketing agency took over an existing mobile puzzle game but ran into difficulties when creating new levels. AITJE analysed the game, built a reusable level design system and linked AITJE Coder to Qwen on its own server. Now, the agency 25 creates new levels every week from a single assignment in OpenCode.

Case study — Marketing agency / level design & in-house coding agency

The marketing agency had acquired a mobile game from a development agency. It was a puzzle game in the style of Candy Crush: the app was fully functional and already live. The agency was able to market the game, but had less experience in managing and expanding the code.

New levels became the stumbling block. A marketer used AI to build them, but each task essentially started from scratch. There was no fixed system for the structure, reusable components or the level of difficulty. As a result, gaps kept appearing in the process.

## The approach

### Opening the correct repository

The marketer opens the game project in OpenCode using the ‘AITJE Coder’ approach. In this way, the agent works with the game’s existing code, components and level design system.

### A series of questions covering25-levels

The brief is now clear: create new levels for 25 based on the design system and the existing level registration. The rules and context are already set out in the project.

### Let Qwen carry on working

The agent uses a Qwen3 API endpoint (6-35B-A3B) on a server under its own management. The development loop generates the level sequence using the reusable components and the information on pace and difficulty.

### Building on the system

The agency is currently operating at a rate of 25 new levels per week. New projects use the same foundation, making scaling up a repeatable process.
