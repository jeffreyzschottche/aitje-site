## Agent & review

From new task to assessed result

### Tasks and multiple repositories

Select the repository, start branch, model and web search. Where necessary, work on linked repositories within your own secure working folder.

### Live progress and stopping

Track files, commands, tests and errors. Stop a task with confirmation; a stalled loop will be given a limited number of restarts.

### Review by file

View changes side by side or one below the other. Provide an assessment and a comment for each file. Compare runs or have a change re-run.

### Approval and Git

A reviewer opens the pull request on GitHub, GitLab or Gitea. GitHub login using a code and a fork where write access is lacking are supported.

### Queue management, scheduling and rounds

Queue or pause the process. Schedule it once, daily, weekly or via cron. Start on a push or a GitHub/Linear issue and run multiple rounds.

### Priority for interactive work

If you are working in an editor or chat yourself, this takes precedence over batch tasks. The queue shows what is pending, running or awaiting review.

## Management & continuity

Your own environment that you can manage

### System and model selection

Configure the standard model and capacity for agent tasks. The local management console remains available even during faults. The box will restart after a power cut.

### Backup and recovery

A nightly database backup, retained for 14 days as standard. Missed backups are made up. Manual backups and restores can be carried out via the management tools.

### Updates and recovery path

Updates use a signed manifest and a health check. If a new version is found to be faulty, the box can revert to the previous version.

### Logbook and retention periods

Administrative actions are recorded in the audit log. Detailed agent and session data are subject to a retention period; meaningless cost tallies are retained for longer.

### Support and telemetry

You determine access for remote support. Sharing usage statistics is disabled by default. Diagnostics and an optional manual health report assist with maintenance.

### Protection and limitation

Agent work runs in a container with CPU, memory and disk limits. Secrets are stored in encrypted form. A watchdog helps to restore services that have crashed.

## Frequently asked questions

### What is ‘AITJE Coder’?

A dedicated environment for coding agents: a local alternative to services such as Claude Code and Codex. Agents read and modify your code, execute commands and complete tasks iteratively.

### Does Coder work with my own tools?

Yes. Claude Code, OpenCode, Codex, Aider, Cline, Continue and other tools connect to your own model environment. The /connect page in the AITJE environment provides the certificate, your private key and a ready-to-use configuration for each tool. You assign tasks to the agent via the web app.

### How much does AITJE Coder cost?

The standalone product costs €699 per environment, with no per-user licence fee. Including basic installation, testing, training and agreed short-term aftercare, an introductory price of €799 applies; the standard price starts at €898. Introductory offer for Assistent and Coder for the first 100 paying customers. Availability will be confirmed in your quotation. Hardware, server hire and additional setup are quoted separately. All amounts are exclusive of VAT.

### Are local models good enough for real-world applications?

For many tasks, certainly – especially if you keep them simple and clear. See how a marketing agency uses AITJE Coder [25 to create new game levels every week](https://aitje.com/en/cases/coder-game-in-24-uur), or request a demo to discuss the possibilities for your own work.

### Can I add another model myself?

Yes. Adding or removing a local model is done within your model environment; AITJE can do this for you either on a stand-alone basis or via an SLA. An administrator can also add an external provider. By default, these models are not accessible to anyone: you grant access to them on a per-user basis.

### Which programming languages and frameworks can AITJE Coder work with?

You can work with all programming languages and frameworks; Coder is not limited to a single fixed stack. You can provide additional documentation, instructions and project agreements via ‘skills’. The quality depends on the chosen model and the available context, so for a specific stack, we will test it against your tasks.

### Can AITJE Coder work on an existing codebase?

Yes. Coder can read, interpret and adapt existing projects. So you don’t need to start a new project. By providing project documentation and clear instructions, you give the agent context regarding the structure and conventions within your codebase.

### How do I determine which files and commands a coding agent is permitted to use?

For tasks carried out via the web app, the agent operates in a secure container with its own copy of the repository. It is permitted to install packages, but cannot access your internal network. You determine access on a per-repository basis; for GitHub, you log in once using a code, without having to create a token yourself. If you use your own tool, such as Claude Code or OpenCode, that tool determines which files and commands the agent is permitted to use.

### Can I review changes from AITJE Coder before they are applied?

Yes. For tasks carried out via the web app, nothing changes until you approve the result. You read the agent’s report and see every line that has been changed. Approving opens a pull request on GitHub, GitLab or Gitea; ‘Changes required’ rejects the request or has the agent start again. When using the tool interactively, your own tool determines when approval is required.

### Can ‘AITJE Coder’ also write tests and detect errors?

Yes. Coder can write tests, run existing tests and investigate errors. To do this, the agent can use your code, error messages and test results to suggest a change. You can then assess the tests and changes yourself.

### Does AITJE Coder need to run on a server in the office?

No. The environment can run on a BOSGAME M5/M6, a suitable Mac mini, existing hardware, a local server, a cloud server with, for example, Hetzner or DigitalOcean, or an AITJE server. The application, agents and model processing can be set up together or separately. AITJE will find the environment that suits your workflow and desired level of independence.

### Can the coding agent schedule tasks and prepare pull requests?

Yes. You can schedule tasks as one-off or recurring, with supported timetables and push or issue events. The server queues the work. The agent works in their own working copy, displays changes and checks, and prepares a pull request after review. The required server, permissions, models and Git services must be available.

### What additional costs are there on top of the product price?

The product price quoted, including basic installation, is not a total price inclusive of hardware. New hardware, server hire, additional setup, support and any external inference are quoted separately. If you choose your own model running on your own computing power, there is no external API token charge; for paid providers, their rates apply.

### Can Coder use external inference via Nebius or AITJE servers?

An administrator can add a supported external model or OpenAI-compatible endpoint, including a suitable Nebius Token Factory integration. AITJE also offers its own data centre servers for models, coding agents and workflow-oriented inference. We test model quality and tool usage against your tasks and set out access, capacity and costs in advance.
